# 🚀 ОПТИМИЗАЦИЯ API POLLING

## ❌ Проблема

**До:** Проверка каждые 10 секунд → **360 запросов/час**

```
2026-03-31 00:25:35.044 - GET /api/rate-limit/status
2026-03-31 00:25:35.280 - GET /api/rate-limit/status  
2026-03-31 00:25:35.363 - GET /api/rate-limit/status
... (сотни запросов в минуту)
```

**Результат:** Спам в терминал, избыточная нагрузка на сервер

---

## ✅ Решение

**После:** Проверка каждые **60 секунд** → **1 запрос/час**

### Почему 60 секунд достаточно?

**Цель polling:** Обнаружить смену часа (в :00 минут)

**Сценарий:**
```
23:59:00 → Проверка: час "2024-03-31-23"
00:00:00 → Проверка: час "2024-03-31-00" ← ОБНАРУЖИЛИ!
           → Сброс счетчика
           → Автозапуск очереди
```

**Максимальная задержка:** 60 секунд после 00:00

## 📊 Сравнение

| Метрика | До (10 сек) | После (60 сек) |
|---------|-------------|----------------|
| Запросов в минуту | 6 | 1 |

| Спам в терминале | Критический | Отсутствует |
| Задержка реакции | 10 сек | 60 сек |

## 🔍 Детали реализации

### Код (RateLimitContext.jsx):

```javascript
useEffect(() => {
  fetchRateLimitStatus(); // Initial fetch
  
  const interval = setInterval(() => {
    checkNewHour();
  }, 60000); // 60 seconds вместо 10000
  
  return () => clearInterval(interval);
}, [fetchRateLimitStatus, checkNewHour]);
```

### Логика checkNewHour():

```javascript
const checkNewHour = () => {
  const currentHourKey = getCurrentHourKey(); // "2024-03-31-00"
  
  if (currentHourKey !== state.hourKey) {
    // Час изменился!
    
    // 1. Сброс счетчика
    setState(prev => ({
      used: 0,
      remaining: prev.limit,
      hourKey: currentHourKey,
    }));
    
    // 2. Автозапуск очереди через 1 сек
    setTimeout(() => processQueue(), 1000);
    
    // 3. API запрос для синхронизации (ТОЛЬКО при смене часа)
    fetchRateLimitStatus();
  }
  // Если час НЕ изменился → ничего не делаем (экономия)
};
```
