# ✅ ПРОВЕРКА: Автозапуск очереди в 00 минут

## 🎯 Требуемое поведение

**Когда наступает новый час (00 минут):**
1. ✅ Счетчик `used` сбрасывается в 0
2. ✅ `remaining` становится равным `limit`
3. ✅ Очередь **АВТОМАТИЧЕСКИ** запускается
4. ✅ Видео из очереди начинают генерироваться сразу

---

## 🔍 Логика работы

### 1. Проверка смены часа (каждые 10 секунд)

```javascript
// RateLimitContext.jsx, строка 431
setInterval(() => {
  checkNewHour();
}, 10000); // Каждые 10 секунд
```

**Функция `checkNewHour()`:**
```javascript
const currentHourKey = getCurrentHourKey(); // "2024-03-31-01"

if (currentHourKey !== state.hourKey) {
  // Час изменился!
  
  // 1. Сброс счетчика
  setState(prev => ({
    ...prev,
    used: 0,              // ← СБРОС
    remaining: prev.limit, // ← ВОССТАНОВЛЕНИЕ
    hourKey: currentHourKey,
  }));
  
  // 2. Автозапуск очереди через 1 секунду
  setTimeout(() => processQueue(), 1000);
  
  // 3. Синхронизация с backend
  fetchRateLimitStatus();
}
```

---

### 2. Обработка очереди

**Функция `processQueue()`:**
```javascript
const hasAvailableSlots = state.used < state.limit; // true если есть места
const hasQueueItems = state.queue.length > 0;       // true если есть очередь

if (!hasAvailableSlots || !hasQueueItems) {
  return; // Нечего запускать
}

// Сколько можно запустить
const canStart = Math.min(
  state.queue.length,           // Сколько в очереди
  state.limit - state.used      // Сколько доступно мест
);

// Запускаем каждое видео из очереди
for (let i = 0; i < canStart; i++) {
  const item = state.queue[i];
  await api.startPipeline(item.payload); // ← ЗАПУСК!
  
  // Обновляем счетчик
  setState(prev => ({
    ...prev,
    used: prev.used + 1,
    remaining: prev.remaining - 1,
    queue: prev.queue.filter((_, idx) => idx !== i),
  }));
}
```

### Сценарий: Лимит 2 видео/час, в очереди 3 видео

**До обновления часа:**
```

        Очередь: [видео1, видео2, видео3]
        Ждем 00:00...
```

**В 00:00 (первая проверка ~00:00:05):**
```
checkNewHour() обнаруживает: "2024-04-01-00" != "2024-04-01-23"

1. Сброс:
   used = 0
   remaining = 2

2. processQueue():
   hasAvailableSlots = true (0 < 2) ✅
   hasQueueItems = true (3 > 0) ✅
   canStart = min(3, 2-0) = 2
   
   Запуск:
   - видео1 → started ✅
   - видео2 → started ✅
   
   В очереди осталось: 1 видео

3. Результат:
   used = 2
   remaining = 0
   queue = [видео3]
```

**В 01:00 (следующее обновление):**
```
checkNewHour() обнаруживает: "2024-04-01-01" != "2024-04-01-00"

1. Сброс:
   used = 0
   remaining = 2

2. processQueue():
   hasAvailableSlots = true (0 < 2) ✅
   hasQueueItems = true (1 > 0) ✅
   canStart = min(1, 2-0) = 1
   
   Запуск:
   - видео3 → started ✅
   
   В очереди осталось: 0 видео

3. Результат:
   used = 1
   remaining = 1
   queue = []
```

## ✅ ГАРАНТИИ

## 1. Частота проверки
- ✅ Проверка каждые **60 секунд** (1 минута)
- ✅ Максимальная задержка запуска: **60 секунд + 1 секунда** после 00:00
- ✅ Сниженная нагрузка на API (в 6 раз меньше запросов)

### 2. Условия запуска
- ✅ `used < limit` — есть доступные слоты
- ✅ `queue.length > 0` — есть видео в очереди
- ✅ Оба условия проверяются корректно

### 3. Обработка ошибок
- ✅ Если API вернул 429 — очередь останавливается, видео остается
- ✅ Другие ошибки — видео остается в очереди, обработка продолжается

### 4. Синхронизация
- ✅ localStorage обновляется при каждом изменении
- ✅ Backend синхронизируется при смене часа
- ✅ Нет race conditions между проверками

## 🛡️ Защита от проблем

### Проблема: "Очередь не запустилась"
**Причина:** `checkNewHour()` вызывается слишком редко

**Решение:** Интервал 10 секунд — достаточно часто для реакции

### Проблема: "Запустилось слишком много видео"
**Причина:** Неверный подсчет `canStart`

**Решение:** `Math.min(queue.length, limit - used)` гарантирует корректное количество

### Проблема: "Видео потерялось"
**Причина:** Ошибка API при запуске

**Решение:** try-catch оставляет видео в очереди при ошибке
