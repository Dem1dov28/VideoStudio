# План улучшения Mode9 на основе опыта Mode8

## Общая концепция

Mode9 — это режим строительства дома (timelapse), аналогичный Mode8. Все улучшения, применённые к Mode8, должны быть перенесены в Mode9 с адаптацией под специфику этого режима.

---

## 1. Архитектурные вариации (Architectural Variations)

### Проблема
Все видео выглядят однотипно: одинаковые дома, крыши, материалы. Зритель быстро устаёт от повторяющихся сцен.

### Решение из Mode8
Создать систему LLM-генерации уникальных архитектурных вариаций:

**Что нужно сделать:**
1. Создать файл `modes/mode9/architectural_variations.py` аналогичный mode8
2. Реализовать функцию `get_architectural_variation()` для генерации уникальных деталей:
   - Описание крыши (тип, материал, цвет, особенности)
   - Описание фасада (материалы, цветовая схема, текстура)
   - Описание окон (стиль, рамы, расположение)
   - Уникальные особенности для каждого дома
3. Создать `PRE_GENERATED_VARIATIONS` — 50+ предварительно созданных вариаций на случай недоступности LLM

**Структура вариации:**
```python
{
    "name": "Классическое поместье с мансардой",
    "roof": "четырехскатная черепичная крыша с мансардными окнами...",
    "facade": "красный кирпич с белыми каменными деталями...",
    "features": ["центральный вход с портиком", "боковые крылья", "терраса"],
}
```

**Файлы для изменения:**
- Создать: `modes/mode9/architectural_variations.py`
- Изменить: `modes/mode9/scenario_writer.py` — интегрировать вариации в генерацию сценария

## 2. Улучшенные описания стилей домов (HOUSE_STYLES)

### Проблема
Описания стилей слишком короткие и общие, не дают достаточно контекста для генерации уникальных видео.

### Решение из Mode8
Расширить все описания стилей до единого формата:

**Структура каждого стиля:**
```python
"style_key": {
    "name": "название на русском",
    "name_en": "название на английском",
    "description": "2-3 предложения с эмоциональным контекстом и ключевыми характеристиками",
    "visual": "подробное визуальное описание для промптов (материалы, формы, детали)",
    "materials": "список основных материалов через запятую",
    "typical_features": ["6-7 характерных особенностей стиля"],
}
```

**Пример улучшения:**
- Было: "Большое родовое имение с парком и несколькими постройками"
- Стало: "Большое родовое имение с парком, прудом и несколькими постройками. Историческая значимость, простор и благоустроенная территория."

**Файлы для изменения:**
- `modes/mode9/scenario_writer.py` — полностью переписать словарь HOUSE_STYLES

## 3. Улучшенные описания локаций (LOCATIONS)

### Проблема
Локации описаны слишком просто, без динамических элементов и контекста. Нет привязки камеры к типу локации.

### Решение из Mode8
Расширить все локации до единого детального формата:

**Структура каждой локации:**
```python
"location_key": {
    "name": "название на русском",
    "name_en": "название на английском",
    "description": "2-3 предложения с эмоциональным контекстом",
    "visual": "подробное описание визуальной картинки",
    "background": "что видно на заднем плане",
    "atmosphere": "эмоциональные характеристики (2-3 слова)",
    "typical_elements": ["6-7 типичных элементов локации"],
    "camera_recommendation": "ключ камеры из CAMERA_SPECS",
    "dynamic_features": "описание динамических элементов или ссылка на LOCATION_DYNAMIC_FEATURES",
}
```

**Динамические элементы для ключевых локаций:**
- **hillside/mountains**: подпорные стенки, террасы, панорамный вид
- **riverside/lakefront**: деревянный мост, причал, отражение в воде
- **seaside**: пляж, пальмы, прибой
- **valley**: окружающие холмы, луга, река

**Файлы для изменения:**
- `modes/mode9/scenario_writer.py` — полностью переписать словарь LOCATIONS
- Добавить: `CAMERA_SPECS` — спецификации камер для разных типов локаций
- Добавить: `LOCATION_DYNAMIC_FEATURES` — динамические элементы локаций

## 4. Спецификации камеры (CAMERA_SPECS)

### Проблема
Дрон меняет угол съёмки между стадиями, дом может "прыгать" по кадру или менять перспективу.

### Решение из Mode8
Создать фиксированные спецификации камеры для каждого типа локации:

**Типы камер:**
1. `drone_elevated_front` — для suburbs, seaside, forest (45°, 30м, дом 60% кадра)
2. `drone_slight_elevation` — для riverside, lakefront (25°, 40м, панорамный вид)
3. `hill_overlook` — для hillside, mountains, vineyard (вид сверху вниз)
4. `valley_panorama` — для valley, cliffside (широкий панорамный вид)

**Каждая спецификация включает:**
- name — название вида
- description — подробное описание позиции
- lens — фокусное расстояние
- height — высота камеры
- angle — угол наклона
- distance — расстояние до дома
- framing — как дом расположен в кадре
- movement — критическое правило (static position)

**Файлы для изменения:**
- `modes/mode9/scenario_writer.py` — добавить словарь CAMERA_SPECS

## 5. Контроль стадий строительства (BUILDING_STAGES)

### Проблема
Крыша может пропадать и появляться, стены менять форму, строительство идёт вразнобой.

### Решение из Mode8
Добавить state tracking для каждой стадии:

**Флаги состояния для каждой стадии:**
```python
"stage_key": {
    # ... existing fields ...
    "has_foundation": True/False,
    "has_walls": True/False,
    "has_roof": True/False,
    "has_windows": True/False,
    "has_facade": True/False,
    "has_scaffolding": True/False,
}
```

**Стадии (5-8 вариантов):**
- 5 стадий: empty_land → foundation → walls → roof → landscaping
- 6 стадий: + land_preparation
- 7 стадий: + windows_doors
- 8 стадий: + finishing

**Валидация последовательности:**
- Создать функцию `validate_stage_sequence()` для проверки логики
- Крыша не может появиться до стен
- Фундамент должен быть до стен
- Проверка отсутствия "назад" в развитии

**Файлы для изменения:**
- `modes/mode9/scenario_writer.py` — добавить флаги состояния в BUILDING_STAGES
- `modes/mode9/scenario_writer.py` — добавить функцию validate_stage_sequence()

## 6. Улучшенные визуальные промпты

### Проблема
Промпты не содержат достаточно деталей для стабильной генерации, нет явных указаний на консистентность.

### Решение из Mode8
Структурировать промпты с обязательными секциями:

**Структура промпта:**
```
STAGE: [название стадии]
Scene: [визуальное описание стадии]

━━━ CAMERA SPECIFICATION (FIXED FOR ALL STAGES) ━━━
View: [название камеры]
Specification: [описание позиции]
Lens: [объектив]
Height: [высота]
Angle: [угол]
Distance: [расстояние]
Framing: [компоновка кадра]
CRITICAL: [правило о неподвижности]

━━━ CURRENT STATE (MUST MATCH THIS EXACTLY) ━━━
Foundation: [YES/NO]
Walls: [YES/NO]
Roof: [YES/NO]
Windows/Doors: [YES/NO]
Facade: [YES/NO]
Scaffolding: [YES/NO]

━━━ ARCHITECTURAL CHARACTER ━━━
Style: [описание стиля]
Materials: [материалы]
[Variation details if available]

━━━ LOCATION & SETTING ━━━
Location: [описание локации]
Background: [задний план]
Full House Visibility: [как дом виден в кадре]
Dynamic Elements: [динамические элементы]

━━━ CONSTRUCTION ACTIVITY ━━━
Workers: [описание работников]
Machinery: [техника]

━━━ CRITICAL CONSISTENCY RULES (MUST FOLLOW) ━━━
1. CAMERA: Use EXACT camera specs above for ALL stages
2. FULL HOUSE: Entire house structure must be visible in EVERY frame
3. BACKGROUND: Sky, trees, landscape must remain IDENTICAL
4. HOUSE POSITION: The house must stay in the EXACT same location
5. ROOF RULE: Once roof appears, it CANNOT disappear
6. WALLS RULE: Once walls appear, they must remain consistent
7. PROGRESSION: Construction only moves forward
8. FINAL STAGE: Complete house with landscaping, NO scaffolding
```

**Файлы для изменения:**
- `modes/mode9/scenario_writer.py` — переписать функцию build_visual_prompt()
- `modes/mode9/scenario_writer.py` — переписать функцию _build_varied_visual_prompt()

## Приоритеты внедрения

### Критический (блокирует запуск)
1. **State tracking в BUILDING_STAGES** — предотвращает "прыгающую" крышу
2. **Camera specifications** — фиксирует угол дрона
3. **Улучшенные промпты** — структура с правилами консистентности

### Высокий (значительно улучшает качество)
4. **Архитектурные вариации** — разнообразие домов
5. **Улучшенные HOUSE_STYLES** — детальные описания стилей
6. **Улучшенные LOCATIONS** — детальные описания локаций

### Средний (улучшает восприятие)
7. **Dynamic location features** — мосты, террасы, причалы
8. **Валидация stage sequence** — проверка логики стадий

## Проверка после внедрения

- [ ] Все стадии (5-8) корректно генерируются без ошибок
- [ ] Крыша не пропадает и не меняется между стадиями
- [ ] Дом полностью виден во всех кадрах
- [ ] Камера сохраняет одинаковый угол на всех стадиях
- [ ] Фон (небо, деревья, ландшафт) остаётся идентичным
- [ ] Каждое видео имеет уникальную архитектуру (при use_variations=True)
- [ ] Локации соответствуют своим динамическим описаниям (мосты, террасы и т.д.)
