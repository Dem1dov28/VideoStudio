# Система лимитов на генерацию видео

## Обзор

Система ограничивает количество видео, генерируемых в час, с возможностью постановки в очередь и автоматическим возобновлением генерации при обновлении лимита.

## Как это работает

### Backend (Python)

**Модуль:** `utils/rate_limiter.py`

- Класс `RateLimiter` отслеживает использование генерации в текущем часу
- Лимит сбрасывается автоматически при наступлении нового часа (в 00 минут)
- Хранение состояния in-memory с синхронизацией через API

**API Endpoints:**

```http
GET /api/rate-limit/status
Response: {
  "limit": 2,
  "used": 1,
  "remaining": 1,
  "hour_key": "2024-03-30-14",
  "next_reset": "2024-03-30T15:00:00"
}

POST /api/rate-limit/set
Body: { "limit": 2 }
Response: { "success": true, "limit": 2 }

POST /api/rate-limit/check
Response: {
  "allowed": true,
  "reason": "Generation allowed",
  "used": 1,
  "limit": 2,
  "remaining": 1
}

POST /api/rate-limit/increment
Response: {
  "success": true,
  "used": 2,
  "remaining": 0
}
```

### Frontend (React)

**Контекст:** `RateLimitContext.jsx`

Управляет состоянием лимитов и очередью:

```javascript
const { 
  limit,           // Текущий лимит (1-3)
  used,            // Использовано в этом часу
  remaining,       // Осталось видео
  queue,           // Очередь на генерацию
  setLimit,        // Установить лимит
  checkAndStartVideo, // Проверить и запустить видео
  addToQueue,      // Добавить в очередь
  removeFromQueue  // Удалить из очереди
} = useRateLimit();
```

**UI Компонент:** `RateLimitPanel.jsx`

Отображает в левом сайдбаре:
- Прогресс использования лимита
- Выпадающий список для установки лимита (1-3 видео/час)
- Список очереди видео

## Использование

### 1. Запуск видео с проверкой лимита

```javascript
// В Generate.jsx все функции запуска используют checkAndStartVideo
const result = await checkAndStartVideo(payload);

if (result.status === 'started') {
  // Видео запущено сразу
  navigate(`/run/${result.session_id}`);
} else if (result.status === 'queued') {
  // Лимит исчерпан, видео добавлено в очередь
  alert('Видео запустится в следующем часе');
}
```

### 2. Настройка лимита

Пользователь выбирает лимит в UI (левая панель):
- 1 видео/час
- 2 видео/час  
- 3 видео/час

Настройка сохраняется в localStorage и восстанавливается после перезагрузки браузера.

### 3. Очередь видео

Когда лимит исчерпан:
1. Видео автоматически добавляется в очередь
2. При наступлении нового часа (в 00 минут) очередь обрабатывается
3. Видео запускаются автоматически в порядке очереди

**Управление очередью:**
- Просмотр: левая панель → раздел "В очереди"
- Удаление: кнопка ❌ рядом с элементом очереди
- Автоматический запуск: при обновлении лимита

## Автоматическое обновление лимита

**Механизм:**

1. Каждые 10 секунд проверяется текущий час
2. Если час изменился (например, было 14:45, стало 15:01):
   - Счетчик использованных видео сбрасывается в 0
   - Обрабатывается очередь (запускаются видео из очереди)
   - UI обновляется автоматически

**Пример:**

```
14:45 - Лимит: 2 видео/час, использовано: 2, очередь: 3 видео
15:00 - Наступил новый час!
        - Сброс: used = 0, remaining = 2
        - Запуск очереди: 2 видео из 3 запущены
        - Осталось в очереди: 1 видео
16:00 - Новый час!
        - Сброс: used = 0, remaining = 2
        - Запуск очереди: 1 видео запущено
        - Очередь пуста
```

## Сценарии использования

### Сценарий 1: Обычная генерация

1. Пользователь устанавливает лимит: 2 видео/час
2. Запускает первое видео → стартует сразу
3. Запускает второе видео → стартует сразу
4. Пытается запустить третье → получает сообщение "Лимит исчерпан"

### Сценарий 2: Ночная генерация

1. Пользователь устанавливает лимит: 1 видео/час
2. Добавляет в очередь 10 видео перед сном
3. Система работает всю ночь:
   - 01:00 → запущено 1 видео
   - 02:00 → запущено 1 видео
   - 03:00 → запущено 1 видео
   - ...
   - 10:00 → все 10 видео готовы

### Сценарий 3: Изменение лимита

1. Было: лимит 2 видео/час, использовано 2
2. Пользователь меняет на 3 видео/час
3. Мгновенно: remaining становится 1 (можно запустить ещё видео)

## Особенности реализации

### 1. Двойная проверка

Лимит проверяется:
- **Frontend:** перед отправкой запроса через `checkAndStartVideo`
- **Backend:** в endpoint `/api/pipeline/start` перед запуском

Это защищает от race conditions и прямого вызова API.

### 2. Синхронизация часов

Frontend сверяет свой hourKey с backend при каждой загрузке страницы. Если рассинхронизация → используется backend значение.

### 3. Обработка ошибок

Если backend недоступен:
- Данные читаются из localStorage
- Очередь продолжает работать локально
- При восстановлении соединения → синхронизация

### 4. Race condition защита

Флаг `isChecking` предотвращает одновременную проверку нескольких запросов.

## Частые вопросы

**Q: Что если перезагрузить страницу?**  
A: Данные восстановятся из localStorage, очередь сохранится.

**Q: Работает ли в нескольких вкладках?**  
A: Да, но считается одна вкладка активной. При открытии нескольких - данные синхронизируются через localStorage.

**Q: Можно ли обойти лимит?**  
A: Нет, проверка на backend prevents direct API calls.

**Q: Как сбросить лимит вручную?**  
A: В консоли браузера:
```javascript
localStorage.removeItem('rateLimit');
location.reload();
```
